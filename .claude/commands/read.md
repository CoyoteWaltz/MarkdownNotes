记录一条阅读笔记。用户会提供 URL 和/或自己的笔记内容。

## 执行步骤

### 1. 获取内容

- 如果有 URL：用 WebFetch 抓取文章内容，提取标题和核心要点（2-5 句话的精炼摘要）
- 如果没有 URL：跳过抓取，直接用用户提供的内容

### 2. 组装条目

格式如下（时间用当前时间）：

```
{timestamp} +0800

[文章标题](url)

> 用户的笔记内容
>
> Claude 摘要（如果用户没给笔记或笔记较短，则补充摘要；如果用户笔记已经很详细，可以不加）
```

- 时间戳格式：`2026.02.12 20:30:00`
- 如果没有 URL，省略链接行，只写标题
- 引用块（`>`）内保留用户原始笔记风格，不要改写用户的话

### 3. 分类确认

根据内容判断应该归入哪个文件，用 AskUserQuestion 让用户确认：

**目标文件映射：**

| 分类 | 文件路径（相对 `08reading/literature_notes/`） |
|------|-----------------------------------------------|
| 技术文章 | `tech/{year}/quarter_{N}.md`（N 由当前月份决定：1-3→1, 4-6→2, 7-9→3, 10-12→4） |
| 个人成长/学习方法/人生哲学/生活方式 | `being.md` |
| 职业发展/创业/公司分析/工作方法 | `career.md` |
| 设计/字体/游戏/视觉艺术 | `art_&_design.md` |
| 理财/投资/经济 | `wealth_management.md` |
| 时事资讯/行业新闻/产品发布 | `tide_&_information.md` |

展示建议的分类，让用户从选项中确认或指定其他文件。

**对于技术文章，同时建议 index.md 的子分类**（6.1-6.11 中的一个）：
- 6.1 React 生态 / 6.2 CSS & 样式方案 / 6.3 构建工具 & 工程化
- 6.4 JS/TS 语言 / 6.5 Node.js & 运行时 / 6.6 SSR & Web 渲染
- 6.7 AI & LLM / 6.8 Rust & 系统编程 / 6.9 网络 & 基础设施
- 6.10 开发工具 & 效率 / 6.11 CS 基础 & 架构

**对于非技术文章，根据目标文件确定 index.md 的大分类**（一~五），子分类参照 index.md 现有结构。

### 4. 写入文件

- 用 Read 读取目标文件，用 Edit 在文件**末尾**追加新条目（在最后一行内容之后空一行再追加）
- 如果目标文件不存在（如新季度），用 Write 创建

### 5. 更新 index.md

- 读取 `08reading/literature_notes/index.md`
- 在对应子分类的列表末尾追加一行：`- 标题（简短描述）— {时期标注}`
  - 技术文章的时期标注如 `2026Q1`
  - 非技术文章不需要时期标注
- 用 Edit 写入

### 6. 完成确认

输出结果：写入了哪个文件、index.md 的哪个分类，以及条目内容的简要回顾。
